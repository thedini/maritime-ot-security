# Maritime OT Security Capstone Team Project

## Project Overview

This semester-long capstone project challenges teams to design and implement a comprehensive security architecture for a fictional modern container vessel, the **M/V CyberSea**. Teams will work through the entire security lifecycle—from reconnaissance and threat modeling to vulnerability assessment and defense architecture design.

## Learning Objectives

By completing this project, students will:

- **Apply** OT security principles to real-world maritime systems
- **Analyze** complex network architectures and identify security gaps
- **Design** defense-in-depth strategies for vessel operational technology
- **Evaluate** threats specific to maritime environments
- **Develop** practical incident response procedures
- **Communicate** technical security concepts to diverse stakeholders
- **Collaborate** effectively in multidisciplinary teams

## Project Scenario

Your team has been hired as security consultants by CyberSea Shipping Lines to conduct a comprehensive security assessment and design a robust security architecture for their newest vessel, the M/V CyberSea. The vessel is a state-of-the-art 300-meter container ship with highly integrated digital systems.

Recent high-profile maritime cyberattacks have prompted the company to proactively strengthen their security posture. Your team must assess the current state, identify vulnerabilities, and propose a practical, cost-effective security solution that meets international maritime cybersecurity standards (IMO MSC-FAL.1/Circ.3, BIMCO guidelines, IEC 62443).

**Budget Constraint**: $500,000 USD for security improvements (hardware, software, training)
**Timeline**: Implementation plan must span 12 months post-approval
**Regulatory Deadline**: Must achieve compliance within 18 months

See [M/V CyberSea Scenario](./mv_cybersea_scenario.md) for complete vessel specifications.

## Team Formation Guidelines

### Team Size
- **3-4 students per team** (exceptions require instructor approval)
- Teams of 3 receive adjusted scope expectations
- Solo projects not permitted (collaboration is essential)

### Team Formation Process
1. **Week 1**: Self-select teams by end of second class session
2. **Week 1**: Submit Team Formation Form with:
   - Team name
   - Member names and contact information
   - Brief statement of each member's background/skills
   - Initial division of responsibilities
3. **Week 2**: Instructor finalizes teams and assigns any unmatched students

### Role Distribution

Each team must designate the following roles (one person can hold multiple roles in 3-person teams):

- **Project Manager**: Coordinates timelines, manages deliverables, facilitates meetings
- **Lead Security Architect**: Oversees technical design, ensures coherence across phases
- **Threat Analyst**: Focuses on threat modeling, vulnerability assessment, risk scoring
- **Communications Lead**: Manages documentation, presentation preparation, report writing

**Note**: All team members contribute to all phases; roles provide focus areas, not exclusive responsibilities.

## Project Phases

The project is divided into four phases aligned with course content:

| Phase | Weeks | Focus Area | Deliverable |
|-------|-------|------------|-------------|
| **Phase 1** | 1-4 | Reconnaissance & Threat Modeling | Asset Inventory & Threat Model |
| **Phase 2** | 5-8 | Vulnerability Assessment | Vulnerability Assessment Report |
| **Phase 3** | 9-12 | Defense Architecture Design | Defense Architecture Document |
| **Phase 4** | 13-14 | Integration & Presentation | Final Presentation & Demo |

### Phase 1: Reconnaissance & Threat Modeling (Weeks 1-4)
**Weight**: 20% of project grade

**Objectives**:
- Document all OT/IT systems aboard M/V CyberSea
- Create detailed network topology diagrams
- Identify critical assets and data flows
- Develop threat models using STRIDE or ATT&CK frameworks
- Assess threat actors and their capabilities

**Deliverable**: Asset Inventory & Threat Model Document (15-25 pages)
**Due**: End of Week 4

See [Phase 1 Details](./phase1_reconnaissance.md)

### Phase 2: Vulnerability Assessment (Weeks 5-8)
**Weight**: 25% of project grade

**Objectives**:
- Identify vulnerabilities in vessel systems
- Analyze attack surface across network segments
- Assess configuration weaknesses
- Evaluate existing security controls
- Develop risk scoring methodology (likelihood × impact)
- Prioritize vulnerabilities for remediation

**Deliverable**: Vulnerability Assessment Report (20-30 pages)
**Due**: End of Week 8

See [Phase 2 Details](./phase2_vulnerability_assessment.md)

### Phase 3: Defense Architecture Design (Weeks 9-12)
**Weight**: 30% of project grade

**Objectives**:
- Design network segmentation strategy
- Plan IDS/IPS deployment
- Develop monitoring and alerting procedures
- Create incident response playbooks
- Specify security controls for each network zone
- Propose security awareness training program

**Deliverable**: Defense Architecture Document (30-40 pages)
**Due**: End of Week 12

See [Phase 3 Details](./phase3_defense_design.md)

### Phase 4: Final Presentation & Demonstration (Weeks 13-14)
**Weight**: 25% of project grade

**Objectives**:
- Present comprehensive security solution
- Demonstrate key technical components
- Defend design decisions
- Address stakeholder concerns
- Provide implementation roadmap

**Deliverable**: Final Presentation (20 minutes) + Demo (10 minutes) + Q&A (10 minutes)
**Date**: Week 14 (finals period)

See [Phase 4 Details](./phase4_final_presentation.md)

## Deliverable Requirements

### Document Standards

All written deliverables must include:

1. **Cover Page**:
   - Project title
   - Team name and members
   - Submission date
   - Document version

2. **Executive Summary** (1-2 pages):
   - High-level overview for non-technical stakeholders
   - Key findings and recommendations
   - Budget summary

3. **Table of Contents**:
   - Numbered sections with page references

4. **Body Content**:
   - Professional formatting (consistent fonts, headers, spacing)
   - Numbered figures and tables with captions
   - Citations for external sources (IEEE or APA style)
   - Technical accuracy and appropriate depth

5. **Appendices** (as needed):
   - Detailed technical specifications
   - Configuration files
   - Extended data tables
   - Supplementary diagrams

6. **References**:
   - Minimum 10 academic/industry sources
   - Properly cited standards (IMO, IEC, NIST, etc.)

### Submission Format

- **File Format**: PDF (primary) + source files (Markdown/LaTeX recommended)
- **File Naming**: `TeamName_PhaseX_YYYY-MM-DD.pdf`
- **Submission Method**: Course LMS + GitHub repository (optional)
- **Late Policy**: 10% deduction per day, max 3 days

## Tips for Success

1. **Start Early**: Each phase builds on the previous; delays compound
2. **Communicate Regularly**: Weekly team meetings minimum
3. **Divide & Conquer**: Parallel workstreams, regular integration
4. **Iterate**: Don't wait until the deadline to refine
5. **Seek Feedback**: Use check-ins to validate direction
6. **Think Practically**: Security must be usable and affordable
7. **Document Everything**: Keep notes, track decisions, maintain version control
8. **Prepare for Presentations**: Practice runs, anticipate questions
