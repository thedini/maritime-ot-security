# Laboratory Assignment Grading Rubric

## Overview

This rubric is used to assess hands-on laboratory assignments in the Maritime OT Security course. All labs are graded out of 100 points across four categories: Technical Accuracy, Documentation, Security Analysis, and Professionalism.

---

## Grading Categories

### 1. Technical Accuracy (40 points)

Assessment of the technical execution and correctness of lab tasks.

| Criteria | Excellent (36-40) | Proficient (32-35) | Developing (28-31) | Needs Improvement (0-27) |
|----------|-------------------|--------------------|--------------------|--------------------------|
| **Task Completion** | All tasks completed correctly with no errors | Most tasks completed with minor errors | Some tasks incomplete or contain significant errors | Many tasks incomplete or incorrect |
| **Tool Usage** | Demonstrates mastery of required tools; uses advanced features appropriately | Uses tools correctly for all required tasks | Basic tool usage with some mistakes | Struggles with basic tool operations |
| **Data Collection** | Captures comprehensive, accurate data; organizes effectively | Captures most required data with minor gaps | Captures some data but missing key information | Incomplete or inaccurate data collection |
| **Technical Problem Solving** | Independently troubleshoots and resolves all issues encountered | Resolves most issues with minimal assistance | Requires guidance for problem resolution | Unable to resolve basic technical issues |

**Scoring Guidelines:**
- 36-40: All technical objectives met, data accurate, demonstrates deep understanding
- 32-35: Most technical objectives met, minor errors in execution or data
- 28-31: Some technical objectives met, significant errors or incomplete work
- 0-27: Major technical deficiencies, incomplete tasks, inaccurate results

---

### 2. Documentation (25 points)

Assessment of written lab reports, code comments, and supporting materials.

| Criteria | Excellent (23-25) | Proficient (20-22) | Developing (17-19) | Needs Improvement (0-16) |
|----------|-------------------|--------------------|--------------------|--------------------------|
| **Report Quality** | Clear, well-organized report with all required sections | Good organization, minor formatting issues | Disorganized or missing some required sections | Poor organization, many missing sections |
| **Screenshots/Evidence** | Comprehensive evidence of all tasks; well-labeled and annotated | Most tasks documented with adequate evidence | Some tasks documented, lacking detail | Minimal or missing documentation |
| **Code/Script Documentation** | All code well-commented and explained; includes design rationale | Most code commented appropriately | Some code commented, lacks clarity | Minimal or no code comments |
| **Writing Quality** | Professional writing, no errors, clear explanations | Minor grammatical errors, mostly clear | Multiple errors, unclear in places | Numerous errors, difficult to understand |

**Scoring Guidelines:**
- 23-25: Comprehensive, professional documentation suitable for reference
- 20-22: Good documentation with minor gaps or formatting issues
- 17-19: Adequate documentation but missing details or poorly organized
- 0-16: Incomplete or unprofessional documentation

---

### 3. Security Analysis (20 points)

Assessment of security thinking, vulnerability identification, and attack/defense analysis.

| Criteria | Excellent (18-20) | Proficient (16-17) | Developing (14-15) | Needs Improvement (0-13) |
|----------|-------------------|--------------------|--------------------|--------------------------|
| **Vulnerability Identification** | Identifies all relevant vulnerabilities; provides detailed analysis | Identifies most vulnerabilities with good analysis | Identifies some vulnerabilities, limited analysis | Minimal vulnerability identification |
| **Attack Analysis** | Thorough analysis of attack vectors, impacts, and preconditions | Good analysis of attacks with minor gaps | Basic analysis, missing key details | Superficial or incorrect analysis |
| **Defense Evaluation** | Critically evaluates defenses; proposes improvements | Evaluates defenses adequately | Basic evaluation of defenses | Little to no defense evaluation |
| **Security Implications** | Connects lab concepts to real-world maritime security scenarios | Makes some real-world connections | Limited real-world connections | No security context provided |

**Scoring Guidelines:**
- 18-20: Demonstrates advanced security thinking and analysis
- 16-17: Shows solid understanding of security implications
- 14-15: Basic security understanding with gaps
- 0-13: Limited security analysis or understanding

---

### 4. Professionalism (15 points)

Assessment of lab conduct, timeliness, ethics, and overall presentation.

| Criteria | Excellent (14-15) | Proficient (12-13) | Developing (10-11) | Needs Improvement (0-9) |
|----------|-------------------|--------------------|--------------------|--------------------------|
| **Timeliness** | Submitted on time | Submitted 1-2 days late | Submitted 3-5 days late | Submitted >5 days late or not at all |
| **Ethical Conduct** | Fully adheres to lab safety and ethical guidelines; cites all sources | Adheres to guidelines, minor citation issues | Some ethical concerns or missing citations | Multiple ethical violations |
| **Following Instructions** | Follows all lab procedures precisely | Follows most procedures correctly | Deviates from some procedures | Ignores procedures or instructions |
| **Presentation** | Professional formatting, clear structure, visually appealing | Good formatting with minor issues | Inconsistent formatting | Poor formatting, unprofessional appearance |

**Scoring Guidelines:**
- 14-15: Professional, ethical, timely submission with excellent presentation
- 12-13: Professional with minor issues in timing or presentation
- 10-11: Some professionalism concerns or late submission
- 0-9: Multiple professionalism issues, very late, or unethical conduct

## Specific Lab Requirements

**All labs must include:**

1. **Cover Page**: Student name, lab number, date, course
2. **Executive Summary**: Brief overview of lab objectives and outcomes (150-300 words)
3. **Methodology**: Description of procedures followed
4. **Results**: Data, screenshots, outputs from all tasks
5. **Security Analysis**: Discussion of security implications
6. **Conclusion**: Summary of findings and lessons learned
7. **References**: Citations for any external resources used
8. **Appendices**: Code, raw data, additional screenshots

**File Submission Requirements:**

- Submit as single PDF file
- Filename format: `LastName_FirstName_Lab##.pdf`
- Code files submitted separately in `.py`, `.sh`, or other appropriate format
- Maximum file size: 25MB

| Delay | Penalty |
|-------|---------|
| 0-24 hours | 5% deduction |
| 24-48 hours | 10% deduction |
| 48-72 hours | 15% deduction |
| 72-120 hours | 20% deduction |
| >120 hours | 50% deduction |
| >7 days | 0 points (no credit) |

**Extension Requests**: Must be submitted at least 24 hours before deadline with valid justification.

---

## Academic Integrity

**Plagiarism and cheating will result in zero points for the assignment and referral to academic affairs.**

Acceptable:
- Collaborating on understanding concepts
- Discussing general approaches
- Helping classmates troubleshoot
- Using instructor-provided resources

Not Acceptable:
- Copying code or reports from others
- Sharing completed work
- Using unauthorized external solutions
- Falsifying data or screenshots

---

## Resubmission Policy

Students may resubmit labs within 1 week of receiving feedback to improve their grade:

- Maximum improvement: 10 points
- Only one resubmission allowed per lab
- Must include summary of changes made
- Resubmissions not accepted for labs more than 2 weeks old
